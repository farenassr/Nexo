# Nexo

Nexo is a modular, multi-tenant SaaS platform for small and mid-sized
businesses that still run daily operations through spreadsheets, chat, paper,
or informal coordination.

The first product vertical is restaurants. The architecture is intentionally
designed so the same core platform can later support clinics, retail, services,
and other operational businesses without changing the tenancy model.

## Product Goal

Nexo provides one operating layer for a company to manage:

- branches and locations
- users, memberships, roles, and permissions
- active business modules
- shared calendars, availability, and blocks
- vertical-specific operations such as restaurant floors, tables, customers,
  and reservations
- external integrations and sync jobs

For the MVP, restaurant is the active vertical. Clinic, retail, payments,
notifications, reporting, and AI assistant workflows are future modules.

## Architecture

Nexo is a .NET Aspire modular monolith:

```text
frontend (React + Vite + TypeScript)
  -> Nexo.Server (FastEndpoints API)
       resolves tenant context, validates membership, permissions, and active
       modules, then executes vertical-slice features
  -> PostgreSQL + Redis + Keycloak + external integrations
```

Main projects:

- `Nexo.AppHost`: local Aspire orchestration for PostgreSQL, Redis, Keycloak,
  API, and frontend.
- `Nexo.Server`: FastEndpoints API, EF Core persistence, module registration,
  and vertical slices under `Modules/<Module>/`.
- `frontend`: React + Vite + TypeScript SPA served through Aspire.

See `AIHarness/architecture.md` for the architecture reference used by agents.

## Stack

```text
Backend:        .NET, FastEndpoints, Mediator, EF Core
Orchestration:  .NET Aspire
Frontend:       React, Vite, TypeScript, Tailwind CSS
Database:       PostgreSQL
Cache:          Redis
Identity:       Keycloak
Testing:        TUnit, Shouldly, NSubstitute, Verify, Testcontainers,
                Aspire Testing
Tenancy:        company_id on tenant-owned rows
Database model: PostgreSQL schemas per module, not per company
```

## Tenancy

Nexo is tenant-isolated by company. The company itself is owned by Keycloak as
an organization/tenant. Nexo does not create an internal `companies` table.

`company_id` is the external Keycloak organization id. It is not generated by
Nexo and is not replaced by an internal GUID. Tenant-owned rows include
`company_id`, and EF Core global query filters enforce company isolation.

Correct database shape:

```text
core.branches
iam.company_memberships
calendar.events
restaurant.reservations
integrations.company_integrations
```

Avoided shape:

```text
tenant_acme.reservations
tenant_demo.reservations
```

The MVP has not wired Keycloak end to end yet. Until that work lands, local
`company_id` resolution is an open implementation item. Do not introduce an
internal company table to fill that gap without an explicit design decision.

## Local Development

Prefer the harness wrappers:

```powershell
./AIHarness/scripts/build.ps1
./AIHarness/scripts/test.ps1
./AIHarness/scripts/harness-check.ps1
```

Canonical commands:

```powershell
dotnet restore Nexo.slnx
dotnet build Nexo.slnx --no-restore
dotnet test Nexo.slnx --no-build
```

Use `Nexo.AppHost` for the Aspire local runtime. See
`docs/azure-infrastructure.md` for local and deployed infrastructure notes.
